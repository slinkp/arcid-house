aRCid house — CRT / bitmap font investigation
================================================
Saved: 2026-05-28 (pause point)

GOAL
----
Render text on the RCade cabinet (low-res ~18" CRT) with single-pixel precision,
matching early-to-mid 1980s arcade game text.


HARDWARE / VIEWPORT (CONFIRMED ON CABINET)
------------------------------------------
  dpr:     1
  vvp:     1
  in:      336×262
  cl:      336×262
  scr:     336×262
  doc:     336×262  (after CSS patch; was 340×270)
  8box:    8.00×8.00

Conclusion: CSS pixels map 1:1 to device pixels. Scaling/DPR is NOT the problem.
The visible viewport is 336×262 (4×8 px smaller than original 340×270 design).

CSS change applied: html/body and #running-app max dimensions set to 336×262.


CURRENT FONT
------------
  Family:  Web437_IBM_Model3x_Alt1 (WOFF in /fonts/)
  Comment in src/style.css @font-face:
    "Normal size is 16px, use even multiples of that. 8px also allowed."

  That font appears to be an 8×16 VGA-style design meant for 16px CSS font-size.
  At 8px the browser scales the glyph down; on the CRT it becomes unreadable.

FINDINGS FROM HARDWARE + PHOTOS
-------------------------------
1. Geometry works: G8, H1/V1, FIL, BOX render as distinct pixels on CRT.
2. 8px bitmap text (8- and 8+): identical, both unreadable on hardware.
   Contrast filter hack does nothing at 8px on this display.
3. #fff text color: helps visibility of graphics/16px somewhat; does not save 8px.
4. 16px bitmap text: readable (best text sample on cabinet). +/- filter unclear.
5. DOM vs CVS: same class of problem (browser font rasterization).
6. PX (pure pixel draw): crisp — proves display can show hard edges when pixels
   are placed directly, not via font engine.
7. System monospace for metrics: much more readable on CRT than bitmap font.
8. CRT shows cyan/teal cast for "white" in photos; high ambient glare in venue.
9. Emulator at dpr 4 does not predict CRT font appearance; use cabinet for text.


WHY 8px CSS FAILS BUT 1980s ARCADES USED "SMALL" TEXT
------------------------------------------------------
Vintage games did not use CSS/@font-face. Text was:
  - Bitmap glyphs in ROM (typically 8×8 or 8×16 pixels per character)
  - Blitted to video RAM at integer coordinates, no anti-aliasing, no scaling
  - High contrast, bold strokes designed for the grid

Our 8px CSS uses a 16px-designed WOFF shrunk by the browser — not native 8×8.


OPTIONS CONSIDERED (NOT YET DONE)
---------------------------------
A. Native 8px bitmap font  ← USER CHOSEN NEXT STEP
   Find a font with a true 8×8 (or 8px-native) design, not scaled from 16px.

B. Stay at 16px with this font
   Use font as designed; rework UI layout for half the character density.

C. Intermediate sizes (10/12/14px)
   Worth testing but non-integer scale of 16px design often looks worse.

D. Canvas glyph atlas / sprite blit
   Pre-bake characters as pixels; drawImage at integer coords.
   Closest to 1980s pipeline; more implementation work.

E. Hybrid UI
   Bitmap for large static labels; system monospace for small dynamic values.
